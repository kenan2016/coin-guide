这是一个 **Simple Exchange (简易高性能交易所)** 项目的完整技术架构总结。

该项目不仅仅是一个简单的 CRUD 系统，而是采用 **LMAX 架构思想**，结合 **内存撮合**、**异步结算** 和 **冷热分离** 等金融级系统设计原则构建的高性能交易系统 MVP。

---

### 1. 🏗 总体设计理念 (Design Philosophy)

* **内存优先 (In-Memory First)**: 交易的核心（撮合、定序）全部在内存中完成，不查数据库，追求微秒级延迟。
* **异步结算 (Async Settlement)**: 下单与记账分离。下单只负责排队，成交后通过消息队列异步落库，保证高吞吐。
* **最终一致性 (Event Sourcing)**: 通过定序和事件回放（Crash Recovery）机制，保证系统重启后状态与数据库严格一致。
* **冷热分离 (Cold/Hot Separation)**: 资金安全设计的核心，隔离在线资金与离线存储。

### 3. 🧩 核心模块详解 (Core Modules)

#### A. ⚡️ 交易核心层 (Trading Core)

这是系统的心脏，处理速度决定了交易所的上限。

* **定序网关 (Sequencer)**: 使用 Redis `INCR` 或 Disruptor `Sequence` 为每个请求分配全局唯一 ID，确保主备一致性。
* **撮合引擎 (Match Engine)**:
* 基于 `Disruptor` 的单线程消费者模式。
* 内部维护 `OrderBook`（买卖盘红黑树/堆）。
* **无锁设计**：因为是单线程，完全去除了 `synchronized`，消除锁竞争。


* **崩溃恢复 (Crash Recovery)**: 启动时自动从 MySQL 加载 `PENDING` 订单，重演内存状态。

#### B. 💰 资产结算层 (Settlement Layer)

* **现货结算**: 基于 Kafka 消息，扣减冻结资金，增加目标资产，扣除手续费。
* **合约结算**: 涉及 **保证金 (Margin)**、**杠杆 (Leverage)**、**盈亏 (PnL)** 计算。
* **账户隔离**: `wallet` (现货) 与 `contract_wallet` (合约) 物理表隔离。

#### C. ☠️ 衍生品风控层 (Risk Engine)

* **独立服务**: 一个死循环的高频定时任务（Reaper）。
* **强平逻辑**: 实时计算 `(保证金 + 未实现盈亏) / 持仓价值`。低于维持保证金率（如 0.5%）时，强制接管仓位并市价平仓。

#### D. 📊 行情数据层 (Market Data)

* **流式计算**: 消费 Kafka 成交数据 -> 更新 Redis 中的当前 K 线 -> 定时归档到 MongoDB。
* **深度快照**: 撮合引擎变动时推送 OrderBook 前 N 档 -> Redis -> 前端。

#### E. 🛡 资金安全层 (Wallet Security)

* **三级架构**: 用户充值地址 -> 热钱包 (5%资金) -> 冷钱包 (95%资金)。
* **扫链服务**: 监听区块链节点，发现用户充值后，自动发起归集交易汇入热钱包。

### 4. 🔄 数据流转全景图 (Data Flow)

#### 场景 1: 用户下单 (High Performance Path)

1. **API**: 鉴权 -> 冻结余额 -> 落库 (状态 PENDING) -> **发布到 Disruptor**。
2. **Engine**: 内存撮合 -> 生成 `TradeEvent` -> **发送到 Kafka**。
3. **Consumer A (结算)**: 消费 Kafka -> 修改数据库余额 (Commit) -> 状态 COMPLETED。
4. **Consumer B (行情)**: 消费 Kafka -> 写入 Redis (K线/成交列表) -> **WebSocket 推送**。

#### 场景 2: 合约爆仓 (Risk Path)

1. **RiskEngine**: 扫描发现用户亏穿维持线。
2. **System**: 锁定仓位 -> 发起**系统市价平仓单** (特权 ID)。
3. **Engine**: 优先撮合该订单。
4. **Settlement**: 平仓后剩余资金注入**风险准备金** (不退给用户)。

### 5. 🛡 安全与鉴权体系

* **API 安全**:
* **JWT (JSON Web Token)**: 无状态认证。
* **ThreadLocal**: 在拦截器解析 Token 并通过线程本地变量传递 `UserId`，实现 Controller 层参数零侵入。


* **资金安全**:
* **热钱包风控**: 设置提现红线，余额不足自动报警，禁止程序触碰冷钱包私钥。
* **内网隔离**: 签名服务与 Web 服务物理隔离。

### 6. 🚀 总结 (Summary)

这个架构是一个**麻雀虽小，五脏俱全**的金融级系统原型。

它避开了传统 Web 项目“数据库即一切”的低效模式，展示了如何通过**内存计算**解决高并发问题，如何通过**消息队列**解决耦合问题，以及如何通过**分层设计**解决金融系统的复杂业务逻辑（如现货与合约的隔离）。

对于学习者来说，掌握这套架构意味着你已经跨过了普通 CRUD 工程师与高并发系统架构师之间的那道门槛。
