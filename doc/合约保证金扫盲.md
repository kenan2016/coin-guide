这两个概念是合约交易（期货）中最核心的**风控参数**。如果不理解它们，写出来的交易所代码会导致用户瞬间亏光，或者交易所被用户亏穿（穿仓）。

我用最通俗的语言，结合**“买房”**的例子来为你解释。

---

### 1. 起始保证金 (Initial Margin) —— “首付”

**是什么？**
这是用户**开仓时**必须掏出来的本金。它是进入赌局的“门票”。

**是多少？**
它取决于用户选择的**杠杆倍数 (Leverage)**。
公式：`起始保证金 = 仓位价值 / 杠杆倍数`

* **例子**：
  你想买 1 个 BTC（假设当前价格 **$10,000**）。
* **1倍杠杆**（现货）：你需要出 **$10,000**（全款买房）。
* **10倍杠杆**：你需要出 **$1,000**（10% 首付）。
* **100倍杠杆**：你需要出 **$100**（1% 首付）。



**代码意义**：
在 `placeOrder` 时，你的代码需要检查 `Wallet.balance >= 起始保证金`，并把这笔钱冻结起来。

---

### 2. 维持保证金 (Maintenance Margin) —— “生死线”

**是什么？**
这是为了维持这个仓位不被强平，账户里**最少最少**必须留下的钱。
一旦你的 `保证金余额 + 未实现盈亏` 低于这个数，交易所就会强制把你的房子卖了（**爆仓/强平**），以保护交易所的钱不被亏掉。

**是多少？**
这个数值**不是用户定的**，而是**交易所规定**的。
通常根据币种的流动性和持仓量分层。对于 BTC 这种主流币，标准维持保证金率通常是 **0.5%**（即 0.005）。

**公式**：`维持保证金 = 仓位价值 * 维持保证金率`

* **例子**：
  你持有 1 个 BTC（价值 $10,000）。
  交易所规定维持保证金率是 **0.5%**。
  那么，**死线 = $10,000 * 0.5% = $50**。

**意味着什么？**
不管你亏得多惨，只要你账户里的钱（本金 - 亏损）还剩 **$50.01**，你就还是安全的。一旦剩下 **$49.99**，系统立即触发爆仓。

---

### 3. 两者之间的“安全垫”

**为什么要设置两个保证金？**

* **起始保证金 ($1,000)**：是你的本金。
* **维持保证金 ($50)**：是交易所的底线。
* **中间的差额 ($950)**：就是**你能亏损的极限**。

如果只有一个保证金（比如本金亏完才平仓），只要行情波动太快（例如一秒暴跌 20%），系统来不及平仓，用户账户就会变成**负数**（穿仓），这时候交易所就得自掏腰包填窟窿。

所以，交易所必须提前动手！在你的钱快亏完、但还没完全亏完（还剩 $50）的时候，把仓位强平掉，**剩下的这 $50 通常会注入“风险准备金”**，而不是退给用户（各家规则不同，有的会退还剩余部分）。

---

### 4. 真实数值参考 (以 Binance BTC/USDT 为例)

业界通常采用**阶梯保证金**制度（持仓越多，维持保证金率越高，因为大额持仓更难平仓）。

| 档位 | 持仓数量 (USDT) | 杠杆倍数 | **维持保证金率 (死线)** | **起始保证金率 (首付)** |
| --- | --- | --- | --- | --- |
| 第 1 档 | 0 - 50,000 | 125x | **0.40%** | 0.8% (125倍) |
| 第 2 档 | 50,000 - 250,000 | 100x | **0.50%** | 1.0% (100倍) |
| 第 3 档 | 250,000 - 1,000,000 | 50x | **1.00%** | 2.0% (50倍) |
| ... | ... | ... | ... | ... |

* **Altcoins (山寨币)**：波动大，风险高，维持保证金率通常更高（如 **1.0%** 或 **2.0%**）。

### 5. 一个完整的爆仓计算案例

假设用户 **100倍杠杆做多**。

1. **开仓**：
* BTC 价格：**$10,000**
* 持仓：1 个 BTC
* **起始保证金**：$10,000 / 100 = **$100** (本金)
* **维持保证金**：$10,000 * 0.5% = **$50** (死线)


2. **行情下跌**：
* BTC 跌到了 **$9,960**。
* 亏损 = ($10,000 - $9,960) * 1 = **$40**。
* 剩余保证金 = $100 (本金) - $40 (亏损) = **$60**。
* **$60 > $50**，**安全**。


3. **继续下跌 (触发生死线)**：
* BTC 跌到了 **$9,950**。
* 亏损 = **$50**。
* 剩余保证金 = $100 - $50 = **$50**。
* **$50 == $50 (维持保证金)** -> **触发强平！**



**总结给你的代码逻辑：**

在你的 `RiskEngine` 中：

```java
// 写死在常量里，或者存在数据库 config 表里
BigDecimal MAINTENANCE_RATE = new BigDecimal("0.005"); // 0.5%

// 1. 算死线金额
BigDecimal maintenanceMargin = positionValue.multiply(MAINTENANCE_RATE);

// 2. 算当前剩余有多少钱
BigDecimal remainingEquity = initialMargin.add(unrealizedPnL); 
// 注意：亏损时 unrealizedPnL 是负数，所以是 add

// 3. 比较
if (remainingEquity.compareTo(maintenanceMargin) <= 0) {
    killPosition(userId); // 杀！
}

```
