`processMarketOrder` 应该在 **`TradeService.placeOrder`** 方法中被调用。

市价单（Market Order）和限价单（Limit Order）最大的区别在于：

1. **冻结资金不同**：限价单冻结 `价格 * 数量`；市价单没有价格，需要**预估**冻结金额。
2. **调用引擎方法不同**：市价单调用 `processMarketOrder`，且**不进队列**（没撮合完的部分直接撤单，即 IOC 策略）。

以下是完善后的代码步骤：

### 第二步：修改 `TradeService.placeOrder` (核心逻辑)

这是改动最大的地方。我们需要根据 `type` 走不同的分支。

**特别注意“市价买入”的难点**：
用户说“我要市价买 1 BTC”，由于不知道成交价是多少，我们很难精确冻结 USDT。

* **MVP 简化方案**：获取当前盘口**卖一价 (Best Ask)**，以此为基准冻结资金。如果成交时价格上涨（滑点），导致冻结资金不够，则停止撮合。

```java
@Service
public class TradeService {
    // ... 注入保持不变 ...

    /**
     * 下单入口 (支持限价 & 市价)
     * @param type 订单类型: LIMIT / MARKET
     */
    @Transactional
    public String placeOrder(Long userId, String symbol, String direction, BigDecimal price, BigDecimal amount, OrderType type) {
        
        // 1. 获取引擎
        OrderBook engine = orderBookMap.get(symbol);
        if (engine == null) return "不支持该交易对";

        // 2. === 计算需要冻结的资金 ===
        BigDecimal freezeAmount = BigDecimal.ZERO;
        String coinToFreeze = "";

        if (type == OrderType.LIMIT) {
            // --- 限价单冻结逻辑 ---
            coinToFreeze = "BUY".equals(direction) ? symbol.split("/")[1] : symbol.split("/")[0];
            freezeAmount = "BUY".equals(direction) ? price.multiply(amount) : amount;
        } 
        else if (type == OrderType.MARKET) {
            // --- 市价单冻结逻辑 (难点) ---
            if ("SELL".equals(direction)) {
                // 市价卖: 很简单，卖多少冻多少 BTC
                coinToFreeze = symbol.split("/")[0]; // BTC
                freezeAmount = amount;
            } else {
                // 市价买: "我要买1个BTC，不管多少钱" -> 需要冻结 USDT
                // 方案: 获取当前"卖一价"，为了安全，可以乘以 1.05 (预留5%滑点)
                // 这里为了 MVP 简单，直接取卖一价
                BigDecimal bestAsk = engine.getBestAskPrice();
                if (bestAsk == null) return "下单失败：盘口无卖单，无法市价买入";
                
                coinToFreeze = symbol.split("/")[1]; // USDT
                freezeAmount = bestAsk.multiply(amount);
            }
        }

        // 3. 检查余额 & 冻结 (DB操作)
        Wallet wallet = walletMapper.selectOne(new QueryWrapper<Wallet>().eq("user_id", userId).eq("coin", coinToFreeze));
        if (wallet == null || wallet.getBalance().compareTo(freezeAmount) < 0) {
            return "下单失败：余额不足";
        }
        // 执行冻结
        wallet.setBalance(wallet.getBalance().subtract(freezeAmount));
        wallet.setFrozen(wallet.getFrozen().add(freezeAmount));
        walletMapper.updateById(wallet);

        // 4. 保存订单到数据库
        OrderEnt order = new OrderEnt();
        order.setUserId(userId);
        order.setSymbol(symbol);
        order.setDirection(direction);
        order.setAmount(amount);
        order.setTradedAmount(BigDecimal.ZERO);
        order.setStatus("PENDING");
        order.setType(type); // 设置类型
        
        // 市价单 Price 设为 0 或者 -1，方便区分
        order.setPrice(type == OrderType.MARKET ? BigDecimal.ZERO : price); 
        
        orderMapper.insert(order);

        // 5. === 调用引擎进行撮合 ===
        synchronized (engine) {
            if (type == OrderType.LIMIT) {
                // A. 限价单: 正常处理
                engine.processOrder(order, this::handleMatch);
            } else {
                // B. 市价单: 调用 processMarketOrder
                // 注意：市价单通常是 IOC (Immediate or Cancel)，即"吃多少算多少，剩下的撤销"
                engine.processMarketOrder(order, this::handleMatch);
                
                // 市价单处理完后，必须检查是否还有剩余未成交的
                // 因为市价单不允许排队 (OrderBook里没有位置存没有价格的单子)
                if (order.getAmount().compareTo(BigDecimal.ZERO) > 0) {
                    System.out.println(">>> 市价单未完全成交，剩余部分自动撤单");
                    cancelOrder(order.getId()); // 调用我们之前写的撤单逻辑，退回多冻结的钱
                } else {
                    // 如果全部成交，标记完成
                    order.setStatus("COMPLETED");
                    orderMapper.updateById(order);
                }
            }
        }

        return "下单成功, ID: " + order.getId();
    }
}

```

### 第三步：补充 `OrderBook` 的辅助方法

在 `TradeService` 的市价买入逻辑中，我们用到了 `engine.getBestAskPrice()`。需要在 `OrderBook` 中加上这个方法。

```java
// OrderBook.java

/**
 * 获取卖一价 (最低卖出价)
 * 用于市价买入时估算冻结金额
 */
public BigDecimal getBestAskPrice() {
    OrderEnt bestAsk = sellQueue.peek();
    return bestAsk == null ? null : bestAsk.getPrice();
}

```

### 第四步：完善 Controller

修改 `ExchangeController`，接受 `type` 参数。

```java
@PostMapping("/order")
public String placeOrder(
        @RequestParam String symbol,
        @RequestParam String direction,
        @RequestParam BigDecimal amount,
        @RequestParam(required = false) BigDecimal price, // 市价单不需要传 price
        @RequestParam(defaultValue = "LIMIT") String type // 默认为限价
) {
    Long userId = UserContext.getUserId();
    OrderType orderType = OrderType.valueOf(type);
    
    // 如果是限价单，必须传价格
    if (orderType == OrderType.LIMIT && (price == null || price.compareTo(BigDecimal.ZERO) <= 0)) {
        return "限价单必须输入价格";
    }
    
    // 如果是市价单，价格设为0
    BigDecimal finalPrice = (price == null) ? BigDecimal.ZERO : price;

    return tradeService.placeOrder(userId, symbol, direction, finalPrice, amount, orderType);
}

```

### 总结逻辑流

1. **用户请求**：`type=MARKET`, `direction=BUY`, `amount=1` (BTC)。
2. **TradeService**：
* 发现是市价买入。
* 问引擎：现在卖一价多少？引擎答：50000。
* Service：冻结用户 50000 USDT。
* Service：生成 `price=0` 的订单入库。


3. **Engine**：
* 调用 `processMarketOrder`。
* 循环吃掉卖一、卖二...
* 如果吃完 1 BTC，回调 `handleMatch` 发送 Kafka 结算。


4. **收尾**：
* 如果此时卖盘不够，只买了 0.8 BTC。
* Service 检测到 `order.amount > 0` (还剩 0.2)。
* Service 自动调用 `cancelOrder`，把这 0.2 BTC 对应的冻结 USDT 退给用户。
* 订单结束。
